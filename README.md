CS student at the intersection of cybersecurity and neuroscience. On the bleeding edge of Linux OSS and systems where security is inegotiable, not a feature checkbox. Long-term, I want to push security hardening and scientific computing forward—applying neuro principles to ML and contributing to hematology research.

Security isn’t an afterthought; it’s architectural. Integrity of data and models matters—compromised intelligence is worse than no intelligence.

Using machines to forward the cause of science.

# Focus
- Cybersecurity
  - Practical hardening, sane defaults, default-deny.
  - Attack-surface reduction, sandboxing, isolation, auditing.
  - Reproducible setups you can reason about and recover.
- Linux/Wayland
  - Minimal compositors, clean configs, reproducible environments.
  - Tooling that serves the operator, not the other way around.
  - Systems that don’t fight you—and don’t surprise you.
- Neuroscience
  - Fundamentals first; application second.
  - Translating neuro principles into general/scientific computing.
  - Data hygiene, interpretability, and ethics baked into pipelines.

# Primary goals
 Server security
  - Identity and access management with least privilege.
  - Network segmentation, secure transport, and monitored boundaries.
  - Data at rest/in transit protections, backups, and recovery drills.
  - Continuous monitoring, logging, and actionable alerts (noise is a vuln).
- Laboratory automation
  - Robust, auditable software for imaging and instrumentation control.
  - Automated pipelines for counting/classifying blood cells.
  - Reproducible analyses for mapping and studying the brain.
- Machine learning and AI
  - Curated, privacy-respecting datasets; traceable training runs.
  - Models to accelerate hematology research and neuro-informed ML.
  - Emphasis on interpretability and verification over leaderboard chasing.
- Neuromorphic computing
  - Architectures and algorithms inspired by the brain.
  - Spiking models, event-driven computation, energy-efficient inference.
  - Bridging theory with deployable systems.

# How I work
- Safety > convenience. Security > boasting.
- Fast is fine; safe is mandatory.
- Reproducible > clever. If it isn’t documented, it didn’t happen.
- Less theater, more patches.
- Fewer knobs, safer defaults.
- Threat-model first; automate the boring, verify the critical.
